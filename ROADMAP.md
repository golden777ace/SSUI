# SSUI — Дорожная карта

Технический план развития библиотеки **Sergievskiy Sergey User Interface**.

Документ живой: решения могут уточняться по мере разработки.

---

## 1. Видение

SSUI — GUI-библиотека для Windows, сочетающая **простоту использования** с **предельно широким набором настроек** и построенная на современном GPU-рендеринге. Ориентир по опыту разработчика — простота Tkinter; ориентир по возможностям и качеству отрисовки — современные фреймворки уровня Flutter/SwiftUI.

### Принципы

- **Скорость и экономия памяти — в основе архитектуры, а не в микрооптимизациях.** Главные рычаги: GPU-рендеринг, перерисовка только «грязных» регионов, data-oriented раскладка данных, отсутствие интерпретатора на горячем пути, аренные аллокаторы. (Ассемблер осознанно не используется: современный компилятор оптимизирует крупный код лучше человека; при необходимости — точечный SIMD после профилирования.)
- **Всё — из примитивов.** Минимальный набор строительных блоков, из комбинаций которых собираются любые виджеты.
- **Декларативность.** Пользователь описывает *что* показать, библиотека решает *как* и *когда* перерисовать.
- **Полная кастомизация.** Элемент = форма в трёх координатах + свойства + правила взаимодействия.

## 2. Зафиксированные технические решения

| Вопрос | Решение | Обоснование |
|--------|---------|-------------|
| Язык ядра | **Rust** | Скорость на уровне C, безопасность памяти без GC (нет пауз сборщика, предсказуемая память), отличный тулинг (cargo), надёжность для долгого соло-проекта. C-ABI сохраняется. |
| Платформа | **Windows only** | Фокус ресурсов, прямой доступ к нативным API. |
| Рендеринг | **GPU: D3D11/12 + Direct2D + DirectWrite** | Нативно для Windows, аппаратное ускорение, первоклассный текст без внешних зависимостей, прямой путь к 3D. |
| Доступ к WinAPI/D3D из Rust | crate `windows` (windows-rs) | Официальные Microsoft-биндинги. |
| Публичный API | **Python 3.11+ через PyO3** | Модель Tkinter: нативное ядро + удобный скриптовый фронт. |
| Парадигма рендеринга | **Retained-mode** | Нужен для декларативного API, constraint-раскладки и экономной перерисовки. |
| Реактивность | **Сигналы (fine-grained)** | Точечное обновление затронутых узлов; быстрее диффинга виртуального дерева. |
| Раскладка | **Гибрид: линейная по умолчанию + constraint-солвер** | Constraint-гибкость там, где нужна; дешёвая линейная — по умолчанию; кэширование геометрии между кадрами. |
| Позиционирование | Constraint + **абсолютное как «аварийный люк»** | Точные координаты без солвера, когда это удобнее. |
| Стилизация | **CSS** (сначала подмножество → полный) | Знакомый синтаксис, низкий порог входа. |
| Темы | **4 сразу:** white, light, dark, black | См. раздел «Дизайн-система». |
| Dev-инструменты | **hot-reload + инспектор дерева/layout** | Удобная разработка и тестирование. |
| Доступность | Мышь + клавиатура (экранные читалки — нет) | По требованиям проекта. |
| IME | Да | Поддержка ввода на разных языках. |
| Лицензия | MIT, соло-разработка | Автор держит копирайт; смена лицензии в будущем возможна (при контрибуциях — через CLA). |

## 3. Архитектура (слои снизу вверх)

1. **Платформенный слой** — Win32: создание окна, цикл сообщений, сырой ввод (мышь, клавиатура, IME), high-DPI, мониторы.
2. **Слой рендеринга** — устройство D3D, абстракция `Canvas` поверх Direct2D/DirectWrite: фигуры, скруглённые прямоугольники, текст, изображения, тени, градиенты, отсечение, слои.
3. **Планировщик кадров и event loop** — ввод → обновление состояния → перекомпоновка грязных узлов → перерисовка повреждённых регионов; тикер анимаций; vsync.
4. **Дерево элементов (scene graph)** — узлы с геометрией в 3 координатах, box-моделью, состоянием; аренные аллокаторы.
5. **Движок раскладки** — линейная + constraint-солвер, кэш решённой геометрии.
6. **Система событий** — hit-testing, capture/bubble, фокус, hover/press/focus.
7. **Стили** — токены → семантические токены → CSS-движок (селекторы, каскад, специфичность).
8. **Виджеты** — примитивы и их композиты.
9. **Реактивность** — сигналы, декларативная композиция, привязка состояния к дереву.
10. **Python-биндинги** — тонкий, эргономичный слой поверх C-ABI ядра.

## 4. Дизайн-система

Своя система, по духу ближе к Apple HIG: сдержанность, чёткая иерархия, минимум цветов. Реализуется как слой **семантических токенов** (фон, поверхность/силуэт, контент, акцент, граница, тень) поверх темы.

### Четыре темы

| Тема | Палитра |
|------|---------|
| **white** | 3 цвета: фон `#FFFFFF`, силуэты `#F5F5F5`, содержимое `#AAAAAA` |
| **light** | до 7 цветов |
| **dark** | до 7 цветов |
| **black** | 3 цвета: фон `#000000`, силуэты `#1A1A1A`, содержимое `#424242` |

Токены также включают: шкалу отступов, типографику, радиусы скругления, тени, длительности/кривые анимаций.

## 5. Модель примитивов и композиции

Идея: свести всё к минимуму строительных блоков, из которых собираются любые виджеты.

**Уровни:**

- **Примитивы рисования** (на Canvas): фигура (rect / rrect / path), текст, изображение.
- **Базовый элемент:** узел с геометрией в 3 координатах, стилем, состоянием и правилами взаимодействия (соприкосновение, наложение и т. п.).
- **Виджеты-примитивы:** `Frame` (контейнер), `Text`, `Button`, `Slider`.
- **Композиты** собираются из примитивов:
  - выпадающий список = кнопка + вызываемый каскад кнопок;
  - чекбокс = кнопка, меняющая состояние/вид;
  - прогрессбар = ползунок, управляемый входным значением, а не мышью;
  - и т. д.

> Примечание: текстовый ввод, скроллинг и виртуализация списков потребуют чуть больше, чем четыре примитива, — это учтено в модели базового элемента заранее, но принцип композиции остаётся ядром.

## 6. Дорожная карта по фазам

Каждая фаза имеет чёткий критерий готовности (Definition of Done). Фазы идут последовательно; сначала — идеальный 2D, амбициозные вещи (3D, физика) вынесены в конец.

### Фаза 0 — Фундамент
- Win32-окно, цикл сообщений, обработка ресайза и закрытия.
- Инициализация устройства D3D11, очистка экрана цветом.
- High-DPI awareness.
- **DoD:** открывается окно, заливается цветом, корректно масштабируется, чисто закрывается.

### Фаза 1 — Canvas и примитивы рисования
- Direct2D/DirectWrite поверх D3D.
- Рисование: rrect, текст, изображение, тени, градиенты, отсечение.
- Система «грязных» регионов, планировщик кадров, vsync.
- **DoD:** на экране рисуются скруглённый прямоугольник с тенью и строка текста; перерисовывается только изменившаяся область.

### Фаза 2 — Дерево элементов и память
- Модель узлов, box-модель (margin/border/padding/content), геометрия в 3 координатах.
- Аренные аллокаторы (закладываем минимум памяти).
- **DoD:** дерево из вложенных фреймов строится и обходится; аллокации идут через арену.

### Фаза 3 — Раскладка
- Линейная раскладка (направление, gap, выравнивание, grow/shrink).
- Constraint-солвер (Cassowary-подобный).
- Абсолютное позиционирование.
- Кэш решённой геометрии между кадрами.
- **DoD:** вложенные фреймы корректно раскладываются линейно и по ограничениям; повторная раскладка без изменений берётся из кэша.

### Фаза 4 — События и ввод
- Hit-testing, диспетчеризация capture/bubble.
- Мышь, клавиатура, фокус, hover/press/focus-состояния.
- **DoD:** элемент реагирует на наведение и клик, фокус переключается с клавиатуры.

### Фаза 5 — Токены, темы, CSS-подмножество
- Слой токенов и 4 темы.
- Парсер CSS-подмножества (селекторы по типу/классу/id, базовые свойства, переменные `--token`).
- Применение стилей к дереву.
- **DoD:** внешний вид элементов задаётся из CSS-файла; переключение между 4 темами работает.

### Фаза 6 — Виджеты-примитивы и композиты
- `Frame`, `Text`, `Button`, `Slider`.
- Первые композиты: чекбокс, выпадающий список, прогрессбар.
- Текстовый ввод (базовый), скроллинг.
- **DoD:** собран рабочий примерный экран из примитивов и композитов.

### Фаза 7 — Python-биндинги и декларативный API
- PyO3-слой поверх C-ABI ядра.
- Сигналы (fine-grained реактивность).
- Декларативная композиция дерева из Python.
- **DoD:** пример из README работает; изменение сигнала перерисовывает только зависимый узел.

### Фаза 8 — Анимации
- Кривые, длительности, интерполяция свойств и токенов, тикер.
- **DoD:** плавные переходы состояний (hover, появление/исчезновение) на 60+ fps.

### Фаза 9 — Dev-инструменты
- Hot-reload CSS и декларативного дерева.
- Инспектор: клик по элементу показывает box, constraints, применённые стили.
- **DoD:** правка CSS применяется без перезапуска; инспектор открывается и показывает данные узла.

### Фаза 10 — Полный CSS, сложные виджеты, IME
- Полный каскад/специфичность CSS.
- Виртуализация списков, таблицы, вкладки, меню, диалоги, тултипы.
- IME для ввода на разных языках.
- **DoD:** список из 100k элементов прокручивается плавно; CJK-ввод работает.

### Фаза 11 — 3D-интерфейсы и физика взаимодействий *(исследовательская фаза)*
- Раскладка и рендеринг в трёх измерениях (глубина).
- Правила взаимодействия элементов: реакция при соприкосновении/наложении.
- Физика взаимодействия объектов.
- **DoD:** прототип 3D-сцены интерфейса с базовыми взаимодействиями по глубине.

## 7. Инструменты и процессы

- **Сборка:** cargo (ядро) + maturin/PyO3 (сборка Python-колеса).
- **Упаковка для конечных пользователей:** setuptools/pip.
- **Тесты:** `cargo test` (ядро) + `pytest` (Python) + визуальная регрессия (снимки кадров, сравнение изображений).
- **Качество:** `clippy` + `rustfmt`; `ruff` + `mypy` для Python.
- **Документация:** mkdocs.
- **CI:** GitHub Actions (Windows-раннеры), сборка колёс, прогон тестов и визуальной регрессии.
- **Бенчмарки:** отдельный набор для контроля fps, памяти и времени старта против baseline (в т. ч. сравнение с Tkinter).

## 8. Риски и открытые вопросы

- **Текст и IME** — исторически самая коварная область; DirectWrite снимает бо́льшую часть боли, но раскладка сложного текста и IME требуют внимания.
- **Constraint vs производительность** — солвер дороже линейной раскладки; снимается гибридом и кэшированием.
- **CSS-каскад** — полноценный движок каскада/специфичности нетривиален; начинаем с подмножества.
- **3D-интерфейсы и физика** — фактически R&D; вынесены в финальную фазу, но архитектура на D3D их не блокирует.
- **Расползание объёма** — главный убийца подобных проектов; дисциплина фаз и критерии готовности — защита от этого.
